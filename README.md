## Запуск и проверка

В PyCharm откройте папку `configuration-management-practice-2`, содержащую
`README.md`, `src` и `run.bat`. Настройте Python 3.10+, откройте Terminal (Alt+F12).
Команды Windows ниже вводятся в PowerShell, строка начинается с `PS C:\...>`.
В этой практической нет REPL: каждый запуск печатает результат и завершается сам.
Вводить `exit` для завершения программы не требуется.

Быстрый запуск третьего этапа без интернета:

```powershell
$graph = "examples/repos/cycle.json"
python -m src.main --package A --version 1.0-r0 --test-repo --repository $graph --max-depth 3
```

Ожидается три узла A, B, C и рёбра A -> B, B -> C, C -> A с версиями.
Цикл не приводит к бесконечному выполнению.
Все примеры и тесты текущего этапа:

```powershell
python examples/demo_stage3.py
python -m unittest discover -s tests -v
```

Тестов третьего этапа — 44; ожидается `OK`.
Намеренные ошибки в демонстрации нормальны: скрипт проверяет коды и фрагменты вывода.
Общий успех подтверждается строкой `Этап 3: все проверки пройдены` и кодом `0`.
Код последней программы в PowerShell: `$LASTEXITCODE`.
`run.bat` принимает те же параметры, что `python -m src.main`.
На Linux/macOS используйте `python3` или оболочку запуска:

```sh
sh run.sh --package A --version 1.0-r0 --test-repo \
  --repository examples/repos/chain.json --max-depth 2
```

Отдельная сборка, установка Alpine и `pip install` не нужны.

Внешний интернет не нужен: HTTP-фикстура раздаётся временно на 127.0.0.1 и свободном порту.

## Параметры CLI

Все настройки приходят из опций, не из конфигурационного файла.

| Опция | Назначение |
| --- | --- |
| `--package NAME` | Обязательное имя анализируемого пакета |
| `--repository SOURCE` | Обязательный HTTP(S) URL или путь к JSON при `--test-repo` |
| `--test-repo` | Включить тестовый репозиторий; по умолчанию выключен |
| `--version VERSION` | Обязательная точная версия корня, например `1.0-r0` |
| `--ascii` | Флаг будущего ASCII-дерева, фактический вывод будет на этапе 5 |
| `--max-depth N` | Неотрицательная глубина BFS, по умолчанию 3 |
| `-h`, `--help` | Справка |

Пропущенные параметры, неизвестные/сокращённые опции, неверные имена, версии,
URL, пути, типы флагов и глубина обрабатываются с ошибкой.
Флаги не принимают значения: `--ascii`, а не `--ascii true`.
Пути с пробелами заключайте в двойные кавычки.
На этапе 1 все настройки выводятся как ключ=значение; сеть не используется.
На этапе 2 настройки заменяются прямыми зависимостями, на этапе 3 — узлами и рёбрами.
Глубина влияет на анализ с этапа 3. ASCII пока не рисуется: флаг даёт пояснение в stderr.

Коды: `0` — успех; `1` — ошибка сети/данных/пакета/версии/зависимости;
`2` — ошибка опций argparse. Диагностика идёт в stderr без traceback для этих ошибок.

## Настоящий Alpine-репозиторий

Необязательная онлайн-демонстрация для этапов 2 и 3:

```powershell
python examples/demo_online.py
```

Она читает официальный индекс, узнаёт доступную версию busybox и явно передаёт её через --version.
Программа всегда требует точную версию. Прямой запуск с версией, проверенной при подготовке:

```powershell
$repo = "https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64"
python -m src.main --package busybox --version 1.37.0-r20 --repository $repo --max-depth 3
```

Репозиторий обновляется: если версия исчезла, будет ошибка, а не подмена другой версией.
Для доступной сейчас версии используйте онлайн-пример.
URL может указывать на каталог или оканчиваться `/APKINDEX.tar.gz`.
URL не должен содержать пробелы, авторизацию, query или fragment.
Один запуск анализирует один индекс и архитектуру: отсутствующие зависимости
не ищутся автоматически в соседних репозиториях, а вызывают понятную ошибку.

## Тестовый репозиторий

UTF-8 JSON, допускается BOM. Имена пакетов — только буквы A–Z:

```json
{
  "packages": [
    {"name": "A", "version": "1.0-r0", "dependencies": ["B>=1.0"]},
    {"name": "B", "version": "1.0-r0", "dependencies": []}
  ]
}
```

Обязательны поля name, version, dependencies; зависимости — массив строк.
Корень содержит только packages. Неверные типы и поля не игнорируются.
Несколько версий имени допустимы; повтор имя=версия и повтор ключа JSON — ошибка.

| Файл в examples/repos | Случай |
| --- | --- |
| `chain.json` | Цепь A -> B -> C -> D, глубина 0/1/2/3 |
| `diamond.json` | Общая зависимость D для B и C |
| `cycle.json` | Цикл A -> B -> C -> A |
| `self_cycle.json` | Петля A -> A |
| `disconnected.json` | Недостижимая от A компонента Z -> Y |
| `versions.json` | Разные версии A и ограничения версий B |
| `missing_dependency.json` | Отсутствующий Z: ошибка при раскрытии |
| `invalid_schema.json` | Неверная запись: ошибка данных |

Все случаи автоматически проверяет `examples/demo_stage3.py`.
JSON описывает данные графа, настройки приложения по-прежнему задаются через CLI.

## Алгоритм и границы анализа

Корень имеет глубину 0. BFS использует очередь deque/popleft без рекурсии.
Глубина — кратчайшее число рёбер от корня. Граничные узлы включаются,
но их зависимости не раскрываются. При глубине 0 показывается только корень;
отсутствующая зависимость за границей не ищется.
Узел имя=версия открывается один раз. Рёбра к посещённым узлам сохраняются:
циклы и общие зависимости не теряются и не вызывают повторного обхода.
Порядок BFS — порядок обнаружения. Порядок загрузки относится к этапу 4.

Поля APKINDEX: P — имя, V — версия, D — ограничения зависимостей,
p — предоставляемые имена, k — приоритет поставщика.
Для so:lib... выбирается пакет-поставщик, а ограничение проверяется по версии
предоставляемого имени, не по версии самого пакета.
!name — конфликт: в графе он не создаёт ребро загрузки.
Прямой вывод этапа 2 сохраняет все исходные элементы D, включая !name.

Операторы: =, <, >, <=, >=, ~, <~, >~. Сравнение версий реализовано самостоятельно:
числовые части, буква, суффиксы alpha/beta/pre/rc/cvs/svn/git/hg/p, hash, ревизия -r.
Это правила APK, а не лексикографическая сортировка или подмена правилами SemVer.
Из подходящих кандидатов предпочитается прямое имя, затем приоритет,
новейшая предоставляемая версия и стабильное разрешение равенства по имени.
Неверсионированному alias для автоматического выбора нужен положительный k.

Строится граф объявленных зависимостей, не глобальный план SAT-решателя.
Разные ограничения могут привести к двум версиям одного имени: они сохраняются отдельно.
Теги репозиториев, checksum-ограничения и неизвестные операторы не поддерживаются
и не подменяются приблизительными зависимостями.
Индекс читается в памяти, включая подписанный многопоточный gzip.
Пакеты не скачиваются и не устанавливаются; криптографическая подпись не проверяется.
Лимиты: HTTP 20 секунд, загрузка 16 МиБ, распакованные данные 96 МиБ.
Архивы фикстур создаются временно и не отслеживаются в Git.

## Функции и файлы

- `src/config.py`: Config хранит шесть параметров; build_parser описывает опции;
  depth_value проверяет глубину; parse_config проверяет согласованность; print_config печатает настройки.
- `src/validation.py`: validate_name, validate_version, validate_url, validate_source проверяют ввод.
- `src/repository.py`: Package.key даёт имя=версия; Repository.__init__ проверяет записи;
  exact выбирает точную версию.
- `src/apk_index.py`: package_from_fields проверяет запись; parse_index разбирает текстовый индекс.
- `src/remote.py`: index_url строит адрес; download_index читает HTTP(S);
  unpack_index получает текст из gzip/tar; load_remote объединяет шаги загрузки.
- `src/dependencies.py`: Dependency хранит ограничение; parse_dependency выделяет его части.
- `src/versions.py`: version_tokens выделяет компоненты; compare_tokens и ending_order сравнивают их;
  compare_versions задаёт порядок; matches_version проверяет ограничение; Kind задаёт типы компонентов.
- `src/resolver.py`: Candidate хранит поставщика; accepts проверяет версию;
  compare_candidates задаёт предпочтения; Resolver.__init__ и add_provides индексируют имена;
  resolve выбирает подходящий пакет.
- `src/json_repository.py`: unique_keys выявляет повторы; test_package проверяет запись;
  load_test_repository читает JSON.
- `src/graph.py`: Graph.add открывает узел; build_graph выполняет BFS.
- `src/display.py`: print_direct — вывод этапа 2; print_graph — результат BFS;
  note_reserved_ascii поясняет отложенный флаг.
- `src/main.py`: main связывает конфигурацию, источник, корень, граф и вывод.
- `examples/common.py`: run_case проверяет код и фрагмент вывода; utf8_environment задаёт кодировку.
- `examples/http_fixture.py`: QuietHandler.log_message убирает журнал;
  tar_bytes и index_archive создают фикстуру; repository_server раздаёт её по HTTP.
- `examples/demo_stage1.py`: arguments и main демонстрируют все опции.
- `examples/demo_stage2.py`: options и main проверяют HTTP и прямые зависимости.
- `examples/demo_stage3.py`: options, check_json_graphs, check_depth_and_errors,
  check_http_graph и main проверяют графы и ошибки.
- `examples/demo_online.py`: main демонстрирует настоящий Alpine URL.
- `examples/run_all.py`: unpack_snapshot создаёт временную копию Git-снимка;
  run_stage запускает пример и тесты; main проверяет три сохранённые ветки.
- `tests`: конфигурация, HTTP/архив, версии, поставщики, JSON, BFS, циклы,
  глубина, цепь из 1500 узлов и полный CLI.
- `docs/REQUIREMENTS.md`: соответствие заданию; `docs/NOTES.md`: связь с лекциями.
