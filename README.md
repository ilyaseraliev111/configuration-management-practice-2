CLI-приложение на Python 3.10+. Внешних зависимостей нет.
Основание: вариант 29 сборника ПР2, страницы 92–94; правила оформления — 4–7.
На первом этапе выводились настройки, на втором вместо них выводятся
прямые зависимости выбранной версии. APKINDEX.tar.gz загружается по HTTP(S)

## Запуск и проверка

Откройте в PyCharm всю папку, содержащую `src`, `README.md` и `run.bat`.
Откройте Terminal (Alt+F12). Команды выполняются в PowerShell; REPL здесь нет.
Каждый запуск заканчивается сам, результат ошибки выводится в stderr.

```powershell
python examples/demo_stage2.py
python examples/demo_online.py
python -m unittest discover -s tests -v
```

`demo_stage2.py` запускает временный HTTP-сервер на 127.0.0.1 и проверяет
положительные и ошибочные случаи. Интернет ему не нужен.
`demo_online.py` использует настоящий Alpine URL: сначала читает индекс,
находит доступную версию busybox, затем явно передаёт её программе.
Он нужен только для отдельной онлайн-демонстрации, не для обычных тестов.

Прямой запуск с точной версией, проверенной при подготовке проекта:

```powershell
$repo = "https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64"
python -m src.main --package busybox --version 1.37.0-r20 --repository $repo
```

Публичный репозиторий обновляется: если эта версия исчезнет, программа
вернёт ошибку вместо подмены версии. Для текущей версии есть `demo_online.py`.
`--repository` принимает также полный URL с окончанием `/APKINDEX.tar.gz`.
Для одного запуска анализируется один указанный репозиторий и архитектура.
Можно использовать `run.bat` с теми же аргументами. На Linux/macOS — `sh run.sh ...`.
Программа интерпретируется: отдельная сборка и `pip install` не требуются.

## Параметры

| Опция | Назначение |
| --- | --- |
| `--package NAME` | Обязательное имя пакета |
| `--repository SOURCE` | Обязательный HTTP(S) URL или путь при `--test-repo` |
| `--test-repo` | Логический флаг тестового репозитория, по умолчанию выключен |
| `--version VERSION` | Обязательная точная версия корневого пакета в синтаксисе APK |
| `--ascii` | Флаг будущего ASCII-дерева; по умолчанию выключен |
| `--max-depth N` | Неотрицательная глубина, по умолчанию 3; корень — 0 |
| `-h`, `--help` | Справка |

Флаги не принимают значения: используйте `--ascii`, а не `--ascii true`.
Для тестового режима требуется существующий файл и имя из букв A–Z.
Пути с пробелами заключайте в двойные кавычки.
Проверяется синтаксис URL, затем доступность сети и формат индекса.
Версия `latest` недопустима: нужно конкретное значение, например `1.0-r0`.
Коды: `0` — успех, `1` — ошибка данных/сети, `2` — ошибка опций. В PowerShell код виден через `$LASTEXITCODE`.
Демонстрационный скрипт требует ожидаемые коды и ключевые фрагменты вывода.
`--max-depth` будет использоваться с этапа 3. `--ascii` пока не рисует дерево:
визуализация относится к этапу 5. JSON-режим анализа также появится на этапе 3;
пока `--test-repo` выдаёт поясняющую ошибку после проверки параметров.

## Формат APKINDEX и связь с лекциями

По лекции о менеджерах пакетов: `P` — имя, `V` — версия, `D` — зависимости,
`p` — предоставляемые имена (например, `so:libc.musl-x86_64.so.1`).
Сохраняется также приоритет поставщика `k`. Значения с двоеточиями не обрезаются.
Поле `D` выводится целиком; отрицательное ограничение `!name` означает конфликт,
а не пакет, который нужно устанавливать. Разрешение поставщиков будет в этапе 3.
По лекции о командной строке: настройки — опции CLI, ошибки — stderr и ненулевой код.
По лекции о Git: каждый этап зафиксирован отдельным Conventional/Scoped Commit.

Текст `examples/apk/APKINDEX` — небольшой учебный индекс с несколькими версиями;
это фикстура, а не полный актуальный снимок Alpine. Архив создаётся временно,
поэтому в Git не отслеживаются бинарные файлы и архивы.
Программа читает метаданные, но не проверяет подпись и не устанавливает пакеты.
Лимиты: HTTP-тайм-аут 20 секунд, загрузка 16 МиБ, распакованные данные 96 МиБ.

Официальное описание формата:
https://wiki.alpinelinux.org/wiki/Apk_spec
