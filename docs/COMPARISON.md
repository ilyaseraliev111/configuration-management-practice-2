# Сравнение порядка загрузки с настоящим apk

Проверено 06.11.2026 в Linux x86_64. Настоящий apk-tools 2.14.13 получен
из официального пакета apk-tools-static 2.14.13-r0 Alpine v3.22/main/x86_64.
Бинарный файл и архивы в Git не добавлялись.
Наш анализатор не вызывает apk для получения зависимостей: менеджер использован
только как независимый эталон этого сравнения.

## Одинаковые исходные данные

Источник индекса:
https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64/APKINDEX.tar.gz

SHA256 сохранённого при проверке индекса:

`2db789b7015a525ef86b5a9f0df71c8b960b76c9b72a79f56250db4292e7feba`

Один и тот же снимок содержит 5647 записей пакетов. Наш код читает этот индекс
своим парсером. Для apk снимок опубликован через локальный HTTP-сервер,
с путём x86_64/APKINDEX.tar.gz относительно корня зеркала. Репозиторий не генерировался
из вымышленных пакетов. Это локальное зеркало настоящего официального снимка.
Для нашего графа использована глубина 30; проверка полноты прошла.

Менеджер запускался с отдельным пустым --root, без уже установленных пакетов.
Инициализация создала только пустую базу, update загрузил индекс, а add --simulate
напечатал порядок без установки пакетов. --allow-untrusted нужен для пустого
тестового root без ключей; криптографическая проверка в этом опыте не выполнялась.

Команды эталона (root — отдельная тестовая папка, mirror — URL локального зеркала):

```sh
apk --root "$root" --arch x86_64 --repository "$mirror" \
  --allow-untrusted --initdb --no-scripts add
apk --root "$root" --arch x86_64 --repository "$mirror" \
  --allow-untrusted update
apk --root "$root" --arch x86_64 --repository "$mirror" \
  --allow-untrusted --simulate add busybox=1.37.0-r20
apk --root "$root" --arch x86_64 --repository "$mirror" \
  --allow-untrusted --simulate add zlib=1.3.2-r1
apk --root "$root" --arch x86_64 --repository "$mirror" \
  --allow-untrusted --simulate add curl=8.14.1-r4
```

Порядок apk взят из строк Installing его stdout, а не из порядка записей APKINDEX.
На всех трёх запусках код 0. Множества идентификаторов имя=версия совпали.
Для каждого ребра нашего графа дополнительно проверено, что в выводе apk
зависимость располагается раньше зависимого пакета.

## Объяснение различий

У busybox и zlib есть одна зависимость musl: допустимый порядок совпадает.
Граф curl имеет 14 узлов и 28 рёбер. В нём несколько готовых независимых узлов;
топологический порядок в общем случае не единственный.
Наш алгоритм Кана выбирает минимальный идентификатор из heapq.
apk использует внутренние правила своего решателя и упорядочивания транзакции.
Например, libssl3 у нас появляется раньше libunistring, а у apk — позже libpsl.
Это не нарушение зависимости: все обязательные отношения предшествования соблюдены.
Общий набор пакетов и конкретные версии при этом одинаковы.

Публичный индекс меняется: повторный онлайн-запуск позже может получить другие версии.
Для сравнения двух программ необходимо использовать один и тот же снимок,
архитектуру, точную версию корня и одинаковое начальное состояние базы.
Циклическому тестовому графу линейный порядок не приписывается: наш режим выдаёт ошибку.

Официальная справка по --root, --simulate и --no-scripts:
https://git-old.alpinelinux.org/apk-tools/tree/doc/apk.8.scd
