# Соответствие заданию: вариант 29, этапы 1–4

Основание: приложенный сборник ПР2, страницы 92–94; правила оформления — 4–7.

## Этап 1. Минимальный прототип с конфигурацией

1. Источник параметров — CLI: src/config.py, стандартный argparse.
2. Все шесть опций: --package, --repository, --test-repo, --version, --ascii, --max-depth.
3. Вывод всех настроек как ключ=значение есть в stage1-config.
   В следующих этапах его заменяет полезный результат анализа.
4. Проверки параметров и ошибок: tests/test_config.py, examples/demo_stage1.py.
5. Этап сохранён отдельным коммитом и веткой stage1-config.

## Этап 2. Сбор данных

1. Используется формат Alpine APKINDEX v2 из репозитория APK.
   Это источник метаданных, рассматриваемый в лекции о пакетах.
2. Repository.exact требует точного совпадения имени и версии корня.
   Фикстура содержит две версии busybox с разными зависимостями.
3. HTTP(S)-загрузка и собственный разбор: src/remote.py, src/apk_index.py.
   Менеджеры пакетов и готовые APK-библиотеки не вызываются.
4. Прямые зависимости выводятся в stage2-fetch. На этапе 3 вместо них выводится граф.
5. Этап сохранён отдельным коммитом и веткой stage2-fetch.

Воспроизводимая HTTP-демонстрация без интернета — examples/demo_stage2.py.
Настоящий Alpine URL — examples/demo_online.py.
Учебная фикстура не выдаётся за полный актуальный публичный индекс.

## Этап 3. Основные операции

1. build_graph использует deque/popleft и не вызывает себя рекурсивно.
2. Глубина корня 0; узлы границы включаются, их зависимости не раскрываются.
   Проверяются глубины 0, 1, 2, 3 и цепь из 1500 узлов.
3. Циклы и петли сохраняются рёбрами; узел не ставится в очередь повторно.
4. --test-repo читает JSON с именами A–Z. Есть цепь, ромб, цикл, петля,
   несвязанные компоненты, версии, границы глубины и неверные данные.
   Автоматическая демонстрация — examples/demo_stage3.py.
5. Этап сохранён отдельным коммитом и веткой stage3-bfs.

## Общие ограничения

- Присутствуют README, .gitignore, src, tests, run.sh и run.bat.
- Архивы, бинарные фикстуры, pycache и настройки IDE не отслеживаются.
- Функции документированы docstring; проверены ограничения строк, длины,
  количества аргументов, сложности и числовых литералов в сравнениях.
- Каждый этап проверяется самостоятельно, а не только итоговая main.
- JSON описывает тестовый граф, а не настройки приложения.
